# tgame

A small language for text adventures, and the tools around it.

```
:: entrance
The cave mouth yawns open.

if not has lamp:
A rusted lamp lies in the dirt.
* Take the lamp -> entrance [get lamp]
end

* Go north -> hall
```

| | |
|---|---|
| **tgame Lite** | plays a `.tgame` — double-click one and it runs |
| **tgame IDE** | the editor — right-click a `.tgame` → *Edit with tgame IDE* |
| **`pip install tgame`** | the same engine as a Python library and command line (`tgame game.tgame`) |
| **`Tgame-IDE.html`** | the IDE as a single file; open it in any browser, no install |

## Install (Windows)

Download `tgame-setup-<version>.exe` from the [latest release](https://github.com/codeiscool772/tgame/releases/latest) and run it.
It installs for your user (no admin prompt), makes `.tgame` files open in Lite, and adds the right-click **Edit with tgame IDE**.
The installer is not code-signed yet, so Windows SmartScreen may show "unknown publisher" the first time.

### Updates

The app checks this repository's GitHub Releases a few seconds after it starts and every six hours. When a newer version is
published it downloads in the background (only the changed parts) and asks before restarting. *Help → Check for updates…*
(Lite) or *Check for updates…* in the IDE's command palette (Ctrl+Shift+P) checks right now.

## Layout

| folder | what |
|---|---|
| `tgame_build/` | the engine (`runtime.js`, `lint.js`), the pieces the single-file IDE is built from (`build.py`), and the engine tests |
| `Tgame-IDE.html` | the built single-file IDE (generated by `tgame_build/build.py`; checked in) |
| `tgame-app/` | the Electron desktop app (Lite + IDE) and its Windows installer |
| `tgame-py/` | the Python library and CLI; tested against transcripts produced by the JavaScript engine |
| `.github/workflows/` | CI, and the release build |

The JavaScript engine is the reference. `tgame-py/tests/conformance.json` is generated from it
(`node tgame_build/gen_conformance.js`) and the Python port must reproduce it exactly: same seed and answers, same transcript.

## Build from source

```
# the single-file IDE
cd tgame_build && npm ci && python build.py && node test.js && node test_page.js && node test_mode.js

# the desktop app (Windows)
cd tgame-app && npm ci --include=dev && npm run dist        # -> tgame-app/dist/tgame-setup-<version>.exe

# the Python library
pip install -e tgame-py pytest && pytest tgame-py
```

`npm ci --include=dev` matters if `NODE_ENV=production` is set on your machine; otherwise npm skips the build tools.

## Releasing

1. Bump `version` in `tgame-app/package.json` (and `tgame-py` if the library changed).
2. Commit, then `git tag v<version>` and `git push --tags`.
3. The *Release* workflow builds the installer on Windows and publishes it as a GitHub Release, together with `latest.yml`
   and the block map that installed copies use to find and download the update.

Installed apps pick the new version up on their next check. A release whose tag doesn't match `package.json` fails on purpose.
