# tgame

Play and lightly manipulate `.tgame` text adventures. Pure Python, no dependencies.

```
pip install tgame
tgame game.tgame
```

That's it: the second line plays the game in your terminal. Everything else is optional.

## Command line

```
tgame game.tgame                   # play (typed numbers, words or "help"; undo / save / load / quit)
tgame check game.tgame             # lint; exit status 1 on errors (--strict: warnings too)
tgame info game.tgame              # title, passages, endings, unreachable passages (--json for everything)
tgame run game.tgame -i "take lamp" -i north --seed 1   # scripted, non-interactive transcript
tgame html game.tgame              # one self-contained HTML page, no network needed
tgame json game.tgame              # the whole structure as JSON
tgame rename game.tgame old new    # rename a passage and every reference to it
```

Saves go to `~/.tgame/saves` (set `TGAME_HOME` to move them). `tgame game.tgame --load` resumes.

## Python

```python
import tgame

tgame.play("game.tgame")                    # same as the command line

g = tgame.load("game.tgame")                # or tgame.loads(text)
g.title, g.author, g.start
g.passages                                  # [PassageInfo(name, line, tags, links, is_ending, text)]
g.lint()                                    # [Problem(sev, n, msg)]  (g.ok is True when there are no errors)
g.stats()                                   # passages, endings, unreachable, words, ...

r = g.run(["take lamp", 0, "Ada"], seed=1)  # headless; answers choices (text or index) and ? questions
r.lines, r.plain, r.ended, r.error, r.vars, r.inventory, r.waiting, r.choices

g.rename_passage("hall", "great-hall")      # updates every ->, >>, @start and `visited`
g.set_meta("author", "Me")
g.add_passage("cellar", "Damp.\n-> END", tags=["dark"])
g.remove_passage("village")                 # returns the passages that still link to it
g.save()                                    # or g.save("copy.tgame")

g.to_html()                                 # a single playable page
g.to_json()
```

Anything that takes a game also accepts a path or the game's text:
`tgame.check(path)`, `tgame.run(text, [...])`, `tgame.to_html(path, "out.html")`.

For tooling there is also the raw event stream: `g.interpreter(seed).run()` is a generator yielding
`text`, `pause`, `input`, `choice`, `end` and `error` events; answer `input` and `choice` events with `.send()`.

## Not for writing games

There is no editor, no validator UI, no authoring helpers. Use the tgame IDE (one HTML file) to write games; this
library is for running them and for small scripted edits.

## Same game, any runtime

The reference runtime is JavaScript. This port reproduces it exactly: the same seed and the same answers give the same
transcript, including random numbers (seeded `mulberry32`), JavaScript-style `==` and number formatting, and the lint
messages. The test-suite checks that against transcripts generated by the JavaScript runtime. A save from one runtime
(`{seed, history}`) replays in the other.

Differences you may notice: identifiers use Python's Unicode word characters, and an `@include` directive does not exist
in either runtime yet.
